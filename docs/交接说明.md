# 正上茶舍动画台 · 交接说明

> 谁接手这个仓库，先读完这一份。读完应该知道：一期怎么做、风格怎么卡、验收标准是什么、哪些东西不能碰。
> 细节文档：`docs/新建一期.md`（脚手架四步）、`docs/动效库.md`（动效函数表）。
> 根目录 `AGENTS.md` 是 Grok App Builder 模板自带的沙盒说明，**不适用本项目**，以本文件为准。

---

## 1. 这是什么

正上茶舍是白茶自媒体，在微信视频号发 **竖版 9:16** 茶知识短视频。每期成片 = **真人口播（马老师）** + **动画插片**，动画分两种：

| 类型                   | 谁做                                    | 内容                                                       |
| ---------------------- | --------------------------------------- | ---------------------------------------------------------- |
| 场景动画               | 用户在 **即梦** 里生成（首帧图 → 视频） | 有 IP 角色「小正」出镜的情景：钩子、生活类比、茶室里的动作 |
| 演示动画（**本仓库**） | 代码生成，Remotion + Canvas             | 图解、对比、大字、口诀卷轴+印章、评论区投票、下期预告      |

- 线上面板：https://tea.ahren.cc.cd/ （无登录，纯静态）。在面板里选期 → 预览每个节拍 → 改字 → 导出 MP4（单个或批量），音效可选「合成」或「分轨」（无音效视频 + 48 kHz 音效 WAV）。
- 面板里改的字只存在**本机浏览器**（localStorage）；动画本身永远以代码为准。
- 部署：**push 到 `main` = 自动部署**（Cloudflare Pages git 项目 `tea-zs-git`，构建命令 `npm run build:static`，产物 `dist-static/`）。所以 `main` 永远要能直接上线。
- 用户在 Final Cut 里剪，工程 **29.97 fps**。

## 2. 一期的完整流程

1. **收到定稿文案**（通常 .docx）。按句子拆成节拍 B1…Bn，逐句标明归 **即梦** 还是 **HTML**，发给用户确认后再动手。拆分原则：有人物、有情景、有生活类比 → 即梦；有数字、对比、分类、口诀、投票、预告 → HTML。
2. **问清本期产品**（哪款茶、包装图）。动画里出现的茶饼/茶盒要像这款产品。
3. **建节拍**：`npm run new:clip -- 21 B1 新老 --episode-title "新茶老茶要不要分开存"`，每拍一个文件夹 `src/remotion/epNN/bX/`（`data.ts` / `draw.ts` / `Comp.tsx` / `index.ts`）。本期共用的物件、计时放 `epNN/kit/`（**没有 index.ts**，面板不会把它当节拍）。新一期**整体复制上一期的 `kit/`** 起手（ep21 的 kit 就是从 ep20 来的），再按本期改。
4. **先按估算语速写**：每拍 `data.ts` 写 `SCRIPT`（这拍对应的口播原文，**与定稿一字不差**），时间点一律写成 `voAt("某个词") ± 帧`，**不要写死秒数**。没录音之前 `vo-times.json` 按约 4.5 字/秒推算。
5. **收到真人口播录音后对齐**（见第 5 节），替换 `kit/vo-times.json`，各拍代码不用改，时间自动跟着口播走。逐拍检查后，把每拍在成片里的起止秒报给用户（`filmNote` 会写进节拍说明）。
6. **自检**（第 7 节验收清单）→ 在分支上提交 → **把改动范围讲给用户，得到同意后再合入 `main`**（= 上线）。
7. 用户发现错字：先提醒他可以**直接在面板右侧文案框里改**、马上生效；需要的话再改代码默认值并部署。

分支约定：每期一个分支 `epNN`，做完 fast-forward 合入 `main`，合完删分支。不留长期分支。

## 3. 风格约束（验收按这个来）

### 画面

- **字少、字大、一个焦点。** 同屏 ≤ 12 字；不要小字、不要副标题、不要一堆标注。观众不该有阅读压力。
- **标杆：ep20 B5 口诀**——卷轴 + 两列大字竖排 + 一枚朱印。信息突出、干净。新镜头向它看齐。
- **字和主体同框时**：字出现，主体带回弹弹向一侧给字让位（字左物右），不要把字硬塞进角落。主体上方空间够时，大字放在主体上方即可，不必让位。
- **用「物」讲事**：茶饼、茶盒、茶柜、紫砂罐、棉纸、茶针……不要用投影卡片、圆角色块、通用图标、PPT 式箭头。
- 底部 **300 px 留给字幕**（`SAFE_BOTTOM`），任何文字和主体都不能压进去；画面四周也别贴边。
- 纸感底：宣纸纹理 + 左上暖窗光 + 暗角 + 颗粒（`renderLayers` 已封装），与即梦场景的光线一致。
- 配色（小正色板）：暖米白 #F3EADB · 燕麦米 #E3CFB4 · 茶褐 #7A4E33 · 竹青绿 #6B7A4F · 朱砂红 #B5332A。朱砂只用于印章、圈、强调，不大面积铺。
- 字体：楷体（霞鹜文楷 LXGW WenKai）为主，宋体（Noto Serif SC）为辅；`kit/draw-kit.ts` 里的 `KAI` / `SONG`。

### 节奏

- **宁慢勿快。** 用户在剪辑里可以加速，减速会掉帧。`kit/fx.ts` 里 `TEMPO = 1.3`、`SPRING_TEMPO = 1.25` 是整体放慢系数，新一期沿用。
- 每个元素在口播说到它时才出现（`voAt`），提前 2–10 帧落定；说完后**停够再退场**，两个信息不要同时抢。投票、金句这类要读的东西，完整同屏后至少再停约 1 秒。
- 缓动全部非线性；物件落地用 `heavyLand`，轻物用 `lightFloat`，落印用 `sealPress`。
- 每拍片尾留 `END_HOLD_SEC`（约 1–1.2 秒）给剪辑接缝。

### 内容

- 小正的原则：**不说教 · 不卖弄 · 不神化功效**。动画里不出现疗效、功效类说法；标准、年份等事实以口播为准。
- 口播为准：画面上的字和口播冲突时，改画面去贴口播（例：ep21 B7 金句按口播改成「年份分开放，香气不打架」）。
- 字要准：例如 ep20 用「饼茶」，不能出现「饪茶」这类错字。

### 小正（IP 角色，只在即梦里出现，代码里不画人）

光头圆脑袋的茶精小孩，细眉、豆豆眼、淡腮红，米色立领盘扣短褂、棕色七分裤、棕布鞋。口头禅「不着急，先喝口茶。」

## 4. 音效规范

- 方向：**动画风为主、写实为辅、没有底噪**。主层用仓库里合成的 `mg-*.wav`（D 大调五声，与品牌古筝同调），写实 foley 作为垫层低约 10 dB：`mgLayer("thump", "cakeThud", 帧)`。
- **品牌声** `brandSignature()`（古筝 + 轻铃）**只用于**口诀落印和收尾金句，别处不用。
- 克制：只给主动作配音，间隔 ≥ 0.5 秒（15 帧）；`ambience` / `roomBed` 保持关闭。
- 预览 = 导出：音效在每拍 `data.ts` 的 `sfxHits()` 里写，预览和导出读同一份。
- 新增或替换 `public/tea/sfx/` 里的文件后，必须跑 `node scripts/sfx/durations.mjs`（否则预览里单次音效不卸载，超过 12 个 `<Audio>` 会报错；`npm test` 会检查）。
- 音效来源与许可证全在 `public/tea/sfx/LICENSES.md`，只允许 CC0 或仓库内合成；可用 `scripts/sfx/build-mograph.py`、`build-foley.py` 一键重建。
- 背景音乐不进仓库、不在动画里混，用户自己在剪辑里加。

## 5. 关键技术点

- **一份 `draw.ts` 同时管预览和导出**：`draw(ctx, elapsedMs, params)` 在 1080×1920 画布上画完整一帧；`Comp.tsx` 只用 `<FxBeat>` / `<FxCanvas>` 调它。不要在 Comp 里另写一套动画——预览必须等于导出。
- **所有动效是「帧号 → 数值」的纯函数**：不用 `Math.random()`、不累积状态；随机用 `hash01` / `rng` / `noise`（确定性）。否则预览和导出、两次导出之间会不一致。
- **计时**：`kit/vo.ts` 的 `makeVoAtFromTimes("bX", {script, …})` 读 `kit/vo-times.json`，`voAt("词", 第几次)` 返回该词第一个字开口的帧（相对本拍起点）。片段长度 `VO.lengthOf(END_HOLD_SEC)`。
- **口播对齐**：
  1. 维护 `kit/vo-segments.json`：按口播顺序列出整条定稿，`key` 是节拍名（与 `makeVoAtFromTimes` 的 key 一致），没有 HTML 节拍的段落（即梦镜头、纯口播）`key` 写 `"-"`。`text` 必须与该拍 `SCRIPT` 一字不差。
  2. `pip install faster-whisper numpy`，然后
     `python3 scripts/vo/align-vo.py 录音.mp3 src/remotion/epNN/kit/vo-segments.json --out src/remotion/epNN/kit/vo-times.json --prompt "本期专有词，逗号隔开。"`
  3. 看打印的每段匹配率；< 70% 的段落逐字核对（专有词放进 `--prompt` 能显著提高识别）。
  4. 用户之后补录气口、换录音，只需重跑这一步。
- **文案可改**：画面上的字一律经 `textOf(params, TEXT, "key")` 读取，并在 `index.ts` 的 `fields` 里登记同一个 key，面板才能改。
- **Node 里看帧**（不开浏览器检查构图）：`scripts/render-frames.mjs`，用法见 `docs/动效库.md`。改完一拍至少抽 3–5 个关键时刻的帧看一遍。
- 已知坑：
  - `@napi-rs/canvas`（导出/Node 渲染）里 `arc` 扫过**正好 2π** 时可能整圈不画 → 封顶 `0.9995` 圈。
  - 预览最多同时挂 12 个 `<Audio>`，靠 `sfx-durations.ts` 卸载（见第 4 节）。
  - Cloudflare 免费版 worker 体积接近 3 MB 上限；纯静态构建不走 worker，别引入大依赖或把资源打进 JS。
  - 片段 id 规则 `ep<期>-<编号小写>`，`new:clip` 会查重。

## 6. 哪些不要动

- **构建与部署**：`package.json` 的 scripts、`scripts/build-static.mjs`、`vite.config.ts`、`tsconfig.json`。（曾有 AI 工具顺手改了构建脚本，这类改动一律不合入。）
- **已上线的期**（`src/remotion/ep18`–`ep21`）：用户已用于成片，除非用户点名要改某一拍，否则不碰。共用的 `src/remotion/shared/` 改动会影响所有旧期，改之前要确认旧期渲染不变。
- **面板与目录**：`src/remotion/catalog.ts`、`src/lib/clip-data.ts`、面板组件。每期只新增 `epNN/` 文件夹，不需要也不应该改它们。
- **音效库**：不删改现有文件（旧期在引用）；只新增。
- Grok 模板遗留（`AGENTS.md`、`server/`、`public/__grok/`、`scripts/grok-pwa-*`、`migrations/`）：不用管，也别删。
- **没有用户同意，不 push `main`**（push 即上线）。

## 7. 验收清单（每拍过一遍）

- [ ] 每个画面只有一个焦点；同屏 ≤ 12 字；没有小字、没有残缺字、没有出画的圈或字。
- [ ] 底部 300 px 没有文字或主体；四周不贴边。
- [ ] 字出现的时刻与口播对上（误差在几帧内）；需要读的东西完整同屏后停够再走。
- [ ] 字与主体同框时有让位，不拥挤。
- [ ] 画面里的字与口播、定稿一致；茶饼/茶盒像本期产品。
- [ ] 音效只在主动作上，无底噪，品牌声只在口诀和金句。
- [ ] 面板里能改到这一拍的所有文字；预览和导出的 MP4 一致。
- [ ] `npm run typecheck`、`npm run build:static` 通过；`npm test` 里音效与期结构相关的测试全过（`grok-pwa` 的 7 条是模板遗留的已知失败，与本项目无关）。
- [ ] 把每拍在成片里的起止秒告诉用户，便于他在 Final Cut 里对位。

## 8. 仓库外的配套约定（不进仓库，供协作参考）

- **即梦提示词**：每个镜头写清口播原句、成片位置、建议时长（5s/10s），分两步——① 首帧（参考小正人物图 + 产品图；纯 2D 国风手绘、平涂淡彩、手绘线稿、无三维/照片质感；竖版 9:16；正上茶舍茶室，每镜换角度：茶水台、博古茶柜、榻榻米茶席…；除包装原有图案外无字）② 视频（参考首帧；开头结尾都写「全程无配乐、无 BGM、无旋律」；只写 2–3 个动作；不张嘴、不看镜头；场景不变、镜头固定；只列需要的音效）。附一段产品外观描述，包装画错时补贴。
- **即梦片子配声**：即梦常自带音乐，去掉原音轨；情景片用写实声（环境音 + 关键动作声，空档里极轻的窗外鸟鸣），与 HTML 节拍的动画风音效区分。
- **背景音乐**：不要中国风；轻快、略快、知识讲解/教程感、垫底推动口播、少弦乐。只负责推荐曲目，混音由用户做。
- **调色**：只调口播镜头，动画不调；桌面红色压一档，肤色保持红润，整体宁轻勿重。
- **封面**（视频号 3:4 与 9:16）：口播帧轻调色 + 两行大标题，标题离四边留足余量（分享页会裁边），9:16 版标题放在画面中部的方形安全区内。
- **发布文案**：与内容相关但不复述答案，戳痛点留悬念，结尾抛评论区问题，加话题标签；另给一个与封面一致的短标题。
