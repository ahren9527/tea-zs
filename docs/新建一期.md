# 新建一期

> 接手前先读 `docs/交接说明.md`（工作流、风格约束、验收标准、改动边界）。

面板、目录、导出管线都是固定的。**每一期只写这一期的动画本身**：`src/remotion/epNN/<节拍>/index.ts` 一保存，面板里就自动出现，不用登记。

## 命令速查

```bash
git switch -c ep23
npm run new:episode -- 23 "白茶能不能放冰箱"   # 复制上一期 kit/，清空口播分段与时间表，写本期标题
# 编辑 src/remotion/ep23/kit/vo-segments.json（见下）
npm run vo:estimate -- 23                       # 录音前按 3.6 字/秒估算每个字的时间
npm run new:clip -- 23 B1 开门大字              # 每拍一次；SCRIPT 自动取自 vo-segments 里 key=b1 的段
npm run new:clip -- 23 B4-1 避光密封            # 文件夹 b4-1，key 也是 b4-1
npm run dev                                     # http://localhost:3000 预览
npm run check:ep -- 23                          # 自检
```

## 1. 口播分段 `kit/vo-segments.json`

整条定稿按**口播顺序**分段，一段一个对象。HTML 节拍的段 `key` = 节拍文件夹名；即梦镜头和纯口播的段 `key` 写 `"-"`（占时间、参与对齐，但不生成节拍）。

```json
[
  { "key": "-", "text": "白茶到底能不能放冰箱？很多人一听就摇头。" },
  { "key": "b1", "text": "冰箱不是不能放，是要防串味、防冷凝水。" },
  { "key": "-", "text": "（即梦镜头：小正从冰箱里拿茶）……" },
  { "key": "b2", "text": "拿出来先别急着拆，回温半天再开袋。" }
]
```

- `text` 必须与定稿**一字不差**（标点可以带，计时只看汉字、数字、字母）。
- 改了分段文字后：录音前 `npm run vo:estimate -- 23 --all` 重估；录音后重跑对齐。
- 临时补一拍：`npm run new:clip -- 23 B9 收尾 --script "口播原文"` 会追加到末尾，顺序不对就手动挪。

## 2. 每拍的四个文件

`new:clip` 生成的是能直接预览的起手代码（一行水墨大字），在它基础上改：

| 文件        | 写什么                                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `data.ts`   | `SCRIPT`（自动填好）、`TEXT`（画面上的字，面板可改）、时间点 `voAt("词") ± 帧`、`END_HOLD_SEC`、音效 `sfxHits()`                      |
| `draw.ts`   | 逐帧画面（1080×1920）：`beginFrame` → `cameraAt` → `renderLayers({ subject })`。物件从 `../kit/objects`，动效从 `../kit/fx`，字用 `inkText` / `fillText` |
| `Comp.tsx`  | 一行：`<FxBeat draw={draw} allTexts={allTexts} hits={HITS} />`，不要改                                                               |
| `index.ts`  | `defineClip({...})`：`fields`（面板可改的文案，key 与 TEXT 一一对应）、`markers`（时间轴标记）、`note`、`exportName`                   |

参考写法：上一期的节拍（目前是 `src/remotion/ep22/b3/`、`b5/`）。可复用的动效见 `docs/动效库.md`。

## 3. 本期 `kit/`

`new:episode` 从上一期整体复制，按本期改：

- `objects.ts`：茶饼、茶盒、袋子、紫砂罐……换成**本期产品**的样子；用不到的旧物件可以删。
- `cake.ts`：茶饼纹理与轮廓。
- `draw-kit.ts`：文字、笔触、标准分层、章节标题等小工具。一般不用改。
- `fx.ts`：动效入口与放慢系数 `TEMPO = 1.3` / `SPRING_TEMPO = 1.25`，沿用。
- `vo.ts`：口播计时，不用改。
- `FxBeat.tsx`：预览组件，不用改。

kit 里**不能有 `index.ts`**，否则面板会把它当成节拍。

## 4. 录音到了以后

```bash
pip install faster-whisper numpy   # 一次即可，另需 ffmpeg
python3 scripts/vo/align-vo.py 录音.mp3 src/remotion/ep23/kit/vo-segments.json \
  --out src/remotion/ep23/kit/vo-times.json --prompt "冰箱，冷凝水，回温。"
cp 录音.mp3 public/tea/vo/ep23.mp3   # 面板「参考口播」对听用
npm run check:ep -- 23
```

各拍代码不用改，时间点自动跟着口播走。逐拍对听，再把每拍的起止秒报给用户（面板节拍说明里有）。

1. `npm run check:ep -- 23`、`npm run typecheck`、`npm run build:static`、`npm test` 全部通过，第 7 节看帧验收过。
2. 把改动范围讲给用户，得到同意。
3. 归档并删掉上一期，合入 `main`：

```bash
git rm -r src/remotion/ep22 public/tea/ep22 public/tea/vo/ep22.mp3   # 有哪个删哪个
git commit -m "ep23 上线，归档 ep22"
git switch main && git merge --ff-only ep23 && git push && git branch -d ep23
```

## 小贴士

- 删除一个节拍 = 删掉它的文件夹，并把 vo-segments 里对应段的 key 改成 `"-"`。
- 片段 id 规则 `ep<期>-<编号小写>`（如 `ep23-b4-1`），脚本会查重。
- 本期图片素材放 `public/tea/epNN/`，代码里用 `"tea/epNN/xxx.png"` 引用。
